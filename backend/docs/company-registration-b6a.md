# 원본을 확인한 회사자료 등록 — B6A

이 단계는 사람이 원본 본문을 확인한 값과 원본 사본을 등록한다. 문서 추출 파이프라인·판정·초안 생성·작업 큐를 호출하지 않는다. 실제 기업 값·원본 경로·등록대장·매니페스트와 복구본은 Git 제외 `backend/.venv/b6a/`에만 보관한다.

## 등록 도구

backend 폴더에서 다음 명령을 사용한다. 기본 실행은 계획 조회이며 DB·파일을 변경하지 않는다. 적용은 사용하지 않은 복구 저널 경로를 요구한다.

```powershell
.venv/Scripts/python.exe manage.py register_reviewed_company .venv/b6a/registration-manifest-private.json
.venv/Scripts/python.exe manage.py register_reviewed_company .venv/b6a/registration-manifest-private.json --apply --backup .venv/b6a/new-recovery-journal.json
```

- 원본 바이트 SHA256과 실제 PDF 페이지 수를 검증한다. 이 작업은 원문 읽기이며 기존 저장 문서의 재추출이나 LLM 호출이 아니다.
- 같은 회사 소유 SHA의 기존 문서는 파일·페이지 수를 대조한 뒤 재사용한다. 같은 바이트를 입력에서 중복 지정하거나 기존 동일 SHA 문서가 여러 개면 중단한다.
- 증서 번호·종류·제목·명의·범위·발급기관과 필드별 근거를 요구한다. 확인한 날짜만 입력한다. 번호 부족 등은 `HOLD` 결정과 `missing_fields`·이유·알려진 값·근거를 원본 메타데이터에 보존하며 정식 `Certificate`를 만들지 않는다.
- 회사 행을 잠그고 빈 필드만 채운다. 기존 비어 있지 않은 값은 보존하고 충돌 목록을 반환한다. 같은 매니페스트 재실행 시 회사·증서의 후속 수동 변경을 덮어쓰지 않는다. 다른 원본의 동일 증서 번호나 달라진 기존 검토 메타데이터는 자동으로 합치지 않는다.
- 적용 전에 회사 원행·원본 연결·매니페스트를 배타적으로 기록하고 트랜잭션으로 등록한다. 실패하면 이번 실행이 만든 파일만 정리한다. 결과 저널은 커밋 직전에 쓰이므로 연결 단절 등으로 커밋이 불명확하면 DB를 재조회한다. 저널만으로 커밋 성공을 단정하지 않는다.

## 종류·출처와 실제 등록 구조

기존 `Certificate.cert_type`에 여성기업·이노비즈·발전사 개발선정품·정비적격·기자재 공급 유자격·기술마켓·원산지수출자·한전 협력사 구분을 추가했다. ISO·특허·중소기업·직접생산의 기존 구분과 API 필드는 유지한다. migration `company.0003`은 choices 상태 변경이며 실제 SQL은 no-op이다.

17개 PDF를 각각 원본 `Document`로 보관했다. 통합 PDF 안의 발전사별 5개 증서는 서로 다른 번호·기관·기간으로 등록해 정식 행은 21개다. 기존 소개서는 그대로 재사용했다. 새 문서는 본문 수동 검토를 뜻하는 `REVIEWED`/`MANUAL`이며 추출 완료로 보고하거나 추출 텍스트를 합성하지 않았다.

- `manual_registration.b6a`: 파일별 목록, 각 자료의 정식 반영/보류 결정, 제한, 미확인 필드와 원본 정보.
- `manual_certificate.<번호 해시>`: 해당 정식 행의 확인한 값, 필드별 물리 PDF 페이지·원문 발췌·확인 방식, 복수 기간과 공동 명의 등.
- `manual_company.<필드>`: 회사 필드의 원본·페이지·발췌·의미 제한. 회사의 `source_documents` 기존 연결도 유지한다.

페이지는 실제 제공 PDF의 1부터 시작하는 물리 쪽수다. 인쇄 쪽수와 다르면 별도로 보존한다. 스캔은 사람이 본 페이지에서 짧게 전사한 발췌를 저장했으며 searchable OCR이나 새로운 추출 결과를 주장하지 않는다. 인용의 레이아웃·띄어쓰기는 실제 원본 이미지가 기준이다.

## 확인 범위의 제한

- 설립 연월만 확인한 값을 임의 날짜로 바꾸지 않았다. 직원수·나라장터 등록 품목은 확인되지 않았으며 직접생산·HS 코드를 G2B 등록으로 옮기지 않았다. 소개서의 기술제휴사 열도 합치지 않았다.
- ISO의 최초 승인·재발행일과 현재 기간 시작일을 구분했다. 특허 공동 명의와 등록일·발급일을 나누고 존속기간을 계산하지 않았다.
- 직접생산의 현재/과거 품목별 기간은 메타데이터에 분리 보존한다. 정식 날짜 필드는 두 현재 품목의 공통 기간이다. 정비 자격 표의 인정 범위는 실제 표시된 열만 사용했다.
- 원산지 증서의 누락된 인쇄 첫 페이지를 생성하지 않았다. 제공된 두 물리 페이지에 번호·명의·품목·기간이 확인돼 보이는 범위만 정식 등록했다. 추가 협정/조건의 완전성은 미확인이다.
- 한전 증서의 파일명과 본문 기간, 소개서 요약과 개별 증서의 차이는 개별 원본 본문을 우선하고 불일치를 기록했다. 원본의 취소·변동·법적 효력이나 발급기관 외부 진위 조회는 수행하지 않았다. 상태값은 기존 모델이 저장 종료일과 기준일로 계산하는 표시다.

## 복구와 검증 기록

변경 전 일관된 PostgreSQL dump와 미디어 ZIP, 원행 목록, SHA 기록이 `.venv/b6a/`에 있다. 실제 복원은 하지 않았다. 복구 시 먼저 격리 DB/별도 미디어 폴더에 복원해 확인한다. 운영 중인 개발 DB를 전체 백업으로 덮어쓰지 않는다.

부분 취소가 필요하면 `rows-before-private.json`·`registration-before.json`·실제 DB를 대조한다. B6A 이후 수동 변경이 있으면 자동 복구를 중단한다. 회사 11개 필드는 현재 값이 B6A 값일 때만 원행으로 되돌리며, 새 인증 행·메타데이터·원본 연결·파일도 B6A에서 추가했고 후속 참조가 없다는 것을 확인한 범위에서만 제거한다. 기존 문서·제품·수동 제품 연결·판정·초안·Job을 함께 되돌리지 않는다.

`inventory-verified-private.md/json`은 원본 17개와 정식 21건을 실제 DB 재조회로 대조한 목록이다. `preservation-verification.json`·`http-verification.json`은 SHA/기존 행/테이블/실제 GET·다운로드 대조 기록이다. 동일 입력으로 두 번째 실제 적용을 실행한 전후 전체 DB 해시는 같았다. 격리 검사는 별도의 합성 PDF를 사용하며 개발 DB의 실제 회사자료에 테스트 데이터를 넣지 않는다.

## 후속 단계

이번 등록은 기존 판정 37개·초안 4종을 갱신하지 않는다. 자료 변경 감지, 결과의 오래됨 표시, 인증/회사 메타데이터의 필드별 위치를 판정 근거 응답에 전달하는 개선은 후속 과제다. 현재 판정 근거가 이 수동 메타데이터의 물리 위치를 자동으로 사용한다고 보고하지 않는다. 재판정·초안 재생성·제품/시료 연결과 관리대장 151행의 정식 전환은 별도 범위다.
