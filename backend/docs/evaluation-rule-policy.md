# 판정 규칙의 자료 부족 처리 — B4B

후속 B5A에서 저장 판정 정의와 활성 프롬프트의 충돌을 별도 백업/새 버전으로 해소하고, 구조화 요약의 고정 page=1·합성 인용을 미확인으로 변경했다. 적용·검증 기록은 `BACKEND_PROGRESS.md`의 B5A를 참조한다. 아래 저장값 미조회·서버 미반영 등은 B4B 작업 당시의 기록이며 현재 상태를 뜻하지 않는다.

2026-10-22. 이번 변경은 `apps/evaluation/rules.py`의 인증·시험규격·제출서류·난연 자료 부족 처리에 한정한다. API verdict 문자열, RuleResult, 권한과 수동 수정/복원 계약은 유지한다. 실제 자료로 판정 정확도를 측정한 결과가 아니다.

## 판정과 위험도

| 결과 | 이번 변경에서의 의미 |
|---|---|
| MET | 해당 규칙이 확인하는 비교 조건을 만족하는 직접 등록 근거가 있음 |
| NEEDS_SUPPLEMENT | 비교 가능한 실제 값·명시적 부정·확인된 만료/조건 초과가 있음 |
| NEEDS_CONFIRMATION | 미등록·미매칭·발행일/기관/원본·제출조건 미상으로 확정 불가 |

빈 조회는 회사의 실제 미보유를 뜻하지 않는다. 필수 인증 미등록·SME 기간 미상·품목 미매칭 등은 확인 필요여도 HIGH 위험을 유지할 수 있다. 성적서/실적의 등록 후보는 원본 제출 적합성 확인과 구분한다. 회사 작성 서류나 직접 비교 가능한 정상 자료를 모두 확인 필요로 낮추지는 않는다.

## 변경한 분기

| 입력 | 이전 의미 | B4B 의미 |
|---|---|---|
| 해당 인증 종류의 행 없음 | 미보유·보완 필요, 인증 취득 안내 | 등록 자료로 확인 불가·확인 필요, 내부 원본/등록 확인 |
| SME null / true+기간 미상 | null은 미확인, true는 유효 판정 가능 | 모두 확인 필요. false·실제 만료는 보완 필요, 알려진 유효기간은 기존 충족 유지 |
| 같은 family의 성적서 없음 | 미보유·시험 의뢰 확정 | 해당 범위의 원본/내부 등록부터 확인 |
| 품목은 있으나 제품 미매칭 | 시험규격에서 회사 전체 성적서 사용 가능 | 확인 필요. 특정 품목에 타 제품/미연결 성적서를 빌리지 않음 |
| 발행일 미상 | 제한 없으면 충족, 제한 있으면 오래된 자료처럼 제외 가능 | 제한 유무와 무관하게 확인 필요. 미상 후보가 있으면 전체를 기간 초과로 단정하지 않음 |
| 명시된 기관 요건의 정보 부족 | 충족+위험 주석 가능 | 확인 필요. 확인된 조건 만족 후보가 있으면 그 후보를 선택 |
| 시험성적서/실적 제출 목록 없음 | 미보유·보완 필요 | 확인 필요와 내부 원본/등록 확인 |
| 제출 목록에 일부 후보 있음 | 제출요건 전체를 충족으로 확대 가능 | 후보 근거만 제공하고 품목·기간·원본·시점 확인 필요 |
| 난연 시험자료 없음 / 제품 미매칭 | 시험 의뢰 확정 / 미정 분기 | 확인 필요. 등록 원본과 제품 선택부터 확인 |

시험규격의 회사 공통 요구는 회사 범위 자료를 조회한다. 품목별 요구는 선택 제품의 자료만 조회한다. 제출 실적 후보도 특정 품목이면 그 제품과 연결된 기록만 보여 주며 기간/금액 수치 판정을 새로 만들지 않았다.

발행일이 알려진 모든 후보가 기존 연령 제한을 넘으면 보완 필요다. 기관 정보의 `비공인`, `미공인`, `미인정`, `인정 없음/취소`, `not accredited`, `non-accredited`, `unaccredited`는 제한된 명시적 부정 표기로 구분한다. 빈값·미확인·알 수 없는 기관 조건은 부정으로 해석하지 않는다. KOLAS를 명시한 요구에 일반 ‘국가공인’만 있는 경우도 미확인이다. 날짜와 기관 요건을 모두 통과하는 후보를 우선하며, 그런 후보가 없지만 충족 가능성이 미상인 후보가 있으면 확인 필요다. 모든 후보에 알려진 실패 조건이 있으면 보완 필요를 유지한다.

기관 검사는 기존 문자열 정보에 대한 최소 구분이며 실제 인정서의 시험 범위/국가/인정 유효성 검증 체계가 아니다. `TEST_STANDARD`의 MET은 이 규칙에서 검사한 등록 규격 family·발행일·명시 기관 정보의 범위다. 별도 원본 제출, 시료 동일성, 판본/조건 전체 충족을 뜻하지 않는다. 원본 제출 확인 상태를 표현하는 필드가 없어 성적서/실적 **제출** 규칙은 후보 존재만으로 MET을 주지 않는다.

확인된 인증 만료, SME false, 명시된 성적서 연령 초과·기관 부정, 공식 Listing 요구에 명시적 비공식 시험만 있는 분기는 보완 필요를 유지한다. 정상 등록 인증/성적서와 기존 허용된 준용 시험·회사 작성 서류의 충족 분기도 보존한다. 공식인증 Boolean 기본 true/‘준용’ 문구 부재 추론, 인증 시작일/복수 기간/예외, 판본·여재/완제품, 고정 page=1, 나머지 치수/등급/효율/차압/실적 규칙은 이번에 개편하지 않았다.

## 기존 정책값의 위치와 검증 범위

아래는 **코드 기본값/기존 구현**이며 현재 개발 DB의 저장값이라고 주장하지 않는다. 설정화되어 있다는 사실과 실제 업무 기준으로 타당하다는 검증은 별개다. B4A는 해당 공고에 대한 허용오차·유효 연수·가중치의 타당성을 검증하지 않았다. 이번 변경에서 업무 숫자나 허용오차를 추가/변경하지 않았다.

| 정책 | 현재 코드/설정 위치 | 남은 확인 |
|---|---|---|
| 같은 풍량 허용차 1% | rules._same_airflow의 고정값 | 적용 시료·계측 불확도에 타당한지, 설정화 필요성 |
| 치수 허용오차 기본 3mm·공칭군 | evaluation.dimension_tolerance_mm / nominal_dimension_map | 공고/도면 허용차와의 우선순위·적용 범위 |
| 인증 만료 임박 기본 90일 | evaluation.cert_expiring_days | 영업/입찰 기준과 시점 경계 |
| 성적서 연령 제한 기본 0(제한 없음) | evaluation.test_report_max_age_years, 요구의 max_age_years 우선 | 공고가 요구하는 기간, 기존 월초 기준 cutoff의 타당성. 발행일 미상과 제한 없음은 다름 |
| 기준일 기본 AUTO | evaluation.reference_date_mode | 과거 공고의 오늘/마감일/공고일을 목적별 구분 |

| 제품 매칭 가중치·문턱·후보 수 | matching.py MATCH_WEIGHTS 0.35/0.30/0.25/0.10, MATCH_THRESHOLD 0.6, TOP_N 3 | 고정값이며 설정화·업무적 보정 미수행 |
| 적합도 점수 범위·LLM 보정폭 | matching.py 0~100, ±10 고정 | 유료 검증/업무적 적정성 미확인 |

## 정의·저장 설정·프롬프트의 차이

`apps/core/defaults.py`와 `apps/llm/prompt_defaults.py`의 VERDICT_DEFINITIONS는 같은 옛 정의를 갖는다. ‘증빙·시험규격 부족/다름·추가 시험 필요’를 넓게 NEEDS_SUPPLEMENT 예시로 포함하여 이번의 **확정 미달과 정보 미상을 분리하는 정의**보다 넓다. evaluation.judge 템플릿은 `{{ verdict_definitions }}`를 사용하고 규칙 판정을 바꾸지 않도록 지시하지만, 규칙이 다루지 않는 부분까지 자동으로 새 의미에 맞춰지지는 않는다.

이번 시작 시 개발 5432/8000 리스너가 없고 DB 읽기 전용 접속이 시간 초과되어 **현재 저장된 AppSetting과 활성 PromptTemplate은 조회 미확인**이다. 기존 개발 서버/DB는 기동·재시작하지 않았다. 소스 정의 차이는 확인했으나 저장값이 현재 기본값과 같다고 추정하지 않았다. 임시 테스트 DB의 기본 시드는 운영 설정 확인을 대신하지 않는다. `seed_app_settings`/`seed_prompts`를 개발 DB에 호출하거나 기존 값/프롬프트를 덮어쓰지 않았다. 실제 LLM 검증 전 저장 정의·활성 프롬프트·규칙 정책을 함께 대조하고, 개정·수동 변경 보존 절차에 따라 합의된 정의로 맞춰야 한다.

## 검증과 서버 반영

새 테스트는 DB를 사용하지 않는 합성 객체와 명시적 설정 대체를 사용하며 Company.load/컨텍스트 DB 로드를 금지한다. 새 회귀의 변경 전 실패를 확인한 뒤 구현했다. 관련 B3A/B2/B1·인증/설정 회귀는 별도 임시 PostgreSQL 15432의 `test_filtech_b4b`에서 실행하며 실제 개발 DB·기업 문서 fixture를 사용하지 않는다. 기존 `company_data` 문서 fixture를 요구하는 옛 테스트는 기대 의미만 갱신했으며 실제 실행 확인과 구분한다. 기존 원본 누락 문제를 skip/복원/삭제해 전체 통과로 처리하지 않는다.

새 규칙은 테스트/별도 프로세스에서만 검증했다. 기존 서버 반영·실제 자료 판정·저장 결과/설정 갱신·제품 연결·LLM 호출은 하지 않았다. 공고 폴더/파일명과 본문 번호의 불일치는 미해결이며 합성 사례를 특정 공고의 정답/적격성 검증으로 사용하지 않는다. 기존 저장 결과는 이번 코드 수정만으로 최신 판정이 되지 않는다. 다음 필수 작업은 [회사자료 개정·재분석 추적](company-data-revision-plan.md)이다.
