# 붙여넣기 공고 기본 정보 API

2026-10-26. 공통 계약의 URL·요청/응답 구조를 그대로 구현했다. 관리자 전용이며 유료 LLM·외부 접속·링크 방문·다운로드·Job 생성이 없다. 등록은 DRAFT/UNREVIEWED이며 요구조건 추출/비교/판정 완료를 뜻하지 않는다. 기존 명시 분석 흐름은 유지한다.

## 미리보기

`POST /api/bids/preview-metadata`, JSON `{"source_text":"..."}`. 인증 없는 요청401, 일반 담당자403. 본문은 비어 있지 않은 문자열, 최대200,000자다. 실패400. 미리보기는 DB에 쓰지 않으며 인증을 제외한 추출 함수는 DB 조회도 하지 않는다.

```json
{
  "source_sha256": "원본 source_text의 UTF-8 SHA-256(64자리)",
  "values": {
    "title": "검증용 필터 구매",
    "notice_no": "TEST-42",
    "estimated_price_krw": 1000,
    "bid_close_at": "2027-01-05T10:00:00+09:00"
  },
  "evidence": {
    "notice_no": {"quote": "공고번호: TEST-42"}
  },
  "warnings": []
}
```

위 JSON은 형식 예시다. 실제로는 모든 자동 필드에 서버가 찾은 `evidence[field].quote`를 제공한다. 인용은 **정규화 전 원문에서 연속 부분 문자열**로 찾을 수 있다. Markdown은 항목/값 사이의 파이프도 포함할 수 있다. 강조용 bbox/문서 페이지를 추정하지 않는다. `values`에 없는 필드는 자동 입력하지 않는다.

### 허용 필드/의미

|필드|형식|명시 항목명 예|
|---|---|---|
|title / notice_no|문자열, 최대300/50자|건명·공고명 / 공고번호·입찰공고번호|
|buyer_org / contracting_org|문자열, 각각200자|수요기관 / 공고기관·발주기관·계약기관|

|procurement_type|문자열, 50자|조달구분|

|budget_krw / estimated_price_krw|원 단위JSON 정수|예산·예산금액·사업예산 / **추정가격만**|

|summary|문자열|공고요약|

그 외 필드(status/extra/id/source_ref/source_text/담당자JSON/발전소 여부 등)는 `notice_metadata.values`에서 거부한다. 추정가격·부가세·합계·기초금액을 합산하거나 예산으로 대체하지 않는다. **공고일시/일자·부가세·합계금액·기초금액·예비가기초금액·추정금액은 기존 전용 필드가 없어 생략**, `UNSUPPORTED_FIELD` 경고와 원문 보존으로 처리한다. `created_at`은 등록 시각이며 공고일시가 아니다. 담당부서만으로 기관을 만들지 않는다. 별도의 공고일시 저장 필드를 추가하려면 후속 모델/API 계약 협의가 필요하다.

일반 텍스트 `항목명: 값`, `항목명 값`, 항목명 다음 줄/탭의 값, Markdown `| 항목명 | 값 |`와 한 행 여러 항목 쌍을 지원한다. 가로표는 **명시 항목명2개 이상의 헤더+Markdown 구분선+동일 열 수의 값 행**을 연결한다. 여러 행의 서로 다른 공고 중 한 행을 임의 선택하지 않고 충돌로 남긴다. `<br>`·`&nbsp;`·공백·강조 `**`는 작업용 텍스트에서만 정리하고 표 구분선은 무시한다. 원문 source_text/해시는 변경하지 않는다. 빈 표 셀을 다음 행 값으로 채우지 않는다. 임의 HTML/복잡한 병합 표/라벨 없는 문장/기간 범위의 의미 해석은 하지 않으며 확인 입력으로 남긴다. 링크도 텍스트일 뿐 방문하지 않는다.

날짜는 명시된 **연·월·일·시·분**이 있어야 한다(초 생략 시00초). 점/슬래시/하이픈/년월일 및 ISO 날짜, 명시 오프셋을 지원하고 한국 시간으로 반환한다. 날짜만 있으면 시각을 만들어 저장하지 않는다. 잘못된 날짜·시각·요일, 시작/마감/개찰 역전도 자동 입력하지 않는다. 날짜를 다른 일정 필드로 옮기지 않는다. 공고번호 길이를 맞추거나 숫자를 덧붙이지 않는다.

경고 형태는 `{field: "필드명" 또는 null, code, message}`다. `INVALID_VALUE`, `CONFLICTING_VALUES`, `DATE_ORDER_CONFLICT`는 해당 자동값 생략, `DUPLICATE_VALUE`는 동일 값 하나만 제시, `UNSUPPORTED_FIELD`는 원문에만 보존, `NO_FIELDS_FOUND`는 확정값 없음이다. 동일 필드의 유효/무효 값이 섞여도 자동 확정하지 않는다. 계약방법/입찰방법 등 같은 저장 필드에 서로 다른 명시값이 있으면 선택을 추정하지 않고 충돌로 남긴다.

## 등록/수동 수정

기존 `POST /api/bids` multipart의 `title`, `source_text`, `files`를 그대로 지원한다. 선택적 `notice_metadata`는 다음 **JSON 문자열**이다(JSON 등록 요청에서는 객체도 허용).

```json
{
  "source_sha256": "미리보기 응답의 실제 해시",
  "values": {"title": "직원 확인 제목", "notice_no": "TEST-42", "estimated_price_krw": 1000},
  "edited_fields": ["title"]
}
```

- 최상위 세 키와 `values` 허용 목록/자료형을 검증한다. 금액은 bool/문자열/음수/64비트 범위 초과를 거부한다. 날짜는 시각이 있는 문자열 또는null, 텍스트는 문자열이며 모델 길이 제한을 적용한다.
- 서버가 **현재 원문 해시와 규칙 추출을 다시 계산**한다. `edited_fields` 밖의 전송값은 원문 재검증 값과 같아야 한다. 부재/충돌/오류로 확정하지 못한 값을 자동값이라고 보내면400이며 공고/첨부를 부분 저장하지 않는다. 클라이언트 evidence/상태/출처 주장은 받지 않는다.
- `edited_fields`는 중복 없는 배열이며 모두 `values` 안에 있어야 한다. 이 값은 `MANUAL`로 기록하고 원문 입증으로 표시하지 않는다. 텍스트는 `""`, 금액/날짜는null로 명시 지울 수 있다(건명은 비울 수 없음). **자동값을 생략하는 것만으로는 삭제되지 않는다**. 삭제도 값을 보내고 edited_fields에 표시해야 한다.
- `notice_metadata` 없이도 확정 기본값을 자동 저장한다. 기존 명시 `title`이 우선하고 `EXPLICIT_INPUT` 수동값으로 잠근다. 메타데이터와 함께 기존 title에도 같은 검증 자동 건명을 반복 전송한 경우는 자동값으로 유지한다. title이 메타데이터 값과 다르면 기존 명시 title 우선이다. 둘 다 없으면 기존 첫 본문 행/파일명 기본 건명을 유지한다.
- 원문은 앞뒤 공백/개행을 포함해 그대로 저장한다. 미리보기 뒤 본문이 바뀌면 이전 해시로 등록할 수 없다. 본문을 정규화해 다시 전송하면 새 미리보기/해시가 필요하다.
- 응답은 기존 상세201과 **읽기 전용 `notice_metadata` 추가 필드**다. 기존 공고는null. `schema=pasted-notice-metadata.v1`, `scope=REGISTRATION_SNAPSHOT`, 원문 해시·등록 시 values·field_sources·서버 evidence·edited_fields·warnings를 반환한다. 원문 자동 근거와 수동값을 구분하며 수동 필드에는 자동 evidence를 붙이지 않는다.
- 이 객체는 **등록 당시 스냅샷**이다. 현재 값은 기존 상세 최상위 필드에서 읽는다. 이후 PATCH는 기존 API/locked_fields를 그대로 사용하며 등록 스냅샷을 다시 쓰지 않는다. 등록 시 수동값과 PATCH 수정값은 기존 `locked_fields`에 저장되어 후속 `apply_notice`가 덮어쓰지 않는다. 잠금 해제는 기존 명시 `unlock_fields` 정책이다.

프런트는 경고/누락을 보여주고, 사용자가 수정/삭제한 필드를 edited_fields에 넣어야 한다. 자동값·원문 근거를 임의 수정해 검증값처럼 보내지 않는다. 공고일시 등 미지원 필드를 폼에서 등록시각/입찰시작으로 대체하지 않는다. 기존 요청/응답 필드는 바꾸지 않았다. 새 읽기 필드는 추가 정보로만 사용하면 된다.

## 실제 확인 예시/검사

제공된 한국가스공사 사례의 필요한 구간만 로컬 `.venv/pasted-notice/`에서 검증했다. 원문/실제 사례 응답은 Git에 재배포하지 않는다. 텍스트·Markdown 각각 **10자리 번호 유지, 건명·추정가격·마감/개찰(+09:00)·납품조건 일치**, 예산·입찰시작 추정0을 확인한다. 공고일시/부가세/합계는 각각 미지원 경고이며 값 혼합이 없다. 날짜 오류·중복 충돌·누락도 별도 검증한다.

실제 저장/조회는 기업 사례를 복제하지 않은 **새 검증용 공고4·5**만 사용했다. 공고4는 메타데이터 확인 등록 후 PATCH, 공고5는 notice_metadata 없는 기존 요청의 명시 제목 우선/자동 입력을 검증했다. 실제 `GET /api/bids/4` 응답 일부:

```json
{
  "id": 4,
  "notice_no": "TEST-PASTE-20261026-A",
  "processing_status": "DRAFT",
  "locked_fields": ["delivery_place", "title"]
}
```

수동 건명/명시 입력 우선·수동 필드 잠금·원문 보존·DRAFT·Job0과 잘못된 등록400의 무저장을 대조했다. 실제 HTTP **45건**(성공200/201 및 예상400/401/403), 격리 **59 passed**(신규49+관련 기존10), 외부 Python socket0. 시작 시 이미 존재하던 **공고1/2/3·기업자료·판정·초안·수동 선택·이력·대기 Job1/2 원행 모두 보존**.
