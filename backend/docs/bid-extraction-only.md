# 공고 한 건의 추출 전용 실행

기존 일반 API는 문서 메타데이터 처리→통합 추출→제품 매칭/적합도→설정에 따른 판정 enqueue 기본 동작을 유지한다. B5B는 승인된 공고 하나에 대해 **공고 정보·품목·요구조건 저장까지만** 실행하는 별도 관리 명령을 사용한다. 전역 설정을 바꾸거나 작업 큐 전체를 처리하지 않는다.

```powershell
# backend에서, 백업/범위/실제 유료 호출 승인 확인 후 지정한 ID만 사용
& .venv/Scripts/python.exe manage.py extract_bid_only --bid-id $targetBidId
```

성공 완료된 공고는 명령이 재실행을 거부한다. 등록/실패 상태여도 기존 제품 선택·적합도·수동/잠금 요구조건·판정·초안이 있으면 유료 호출 전에 중단한다. 복구가 필요하면 기존 실제 응답과 원인을 먼저 확인하며 반복 호출로 결과를 고르지 않는다. B5B의 실제 완료 ID에 위 명령을 다시 실행할 필요는 없다.

## 실행 경로와 보존

- `add_attachment`의 기존 `_quick_process`로 로컬 파싱·규칙 분류.
- `extract_bid(..., extraction_only=True)` → `process_attachments(..., parse_only=True)`. `run_pipeline`의 유료 문서 분류/메타데이터·회사 매핑 단계를 호출하지 않는다.
- 전체 첨부 입력 구성 → `services.run_task("bid.extract", files=...)` → 공고 정보·품목·요구조건·placeholder·출처 검토 저장.
- 제품 매칭·EvaluationContext/회사자료 로드·기술 적합도·판정·초안은 호출하지 않는다. 새 공고의 `fit_score`는 null, 매칭·판정 데이터도 없다.
- 작업 handler를 사용하는 경우에도 `payload.extraction_only`가 Boolean true일 때만 같은 분리를 적용하고 자동 판정 enqueue를 건너뛴다. 일반 API는 이 flag를 자동으로 켜지 않는다.

## 스캔 PDF와 출처

빈 텍스트 PDF는 기존 `FileInput`/제공자 원본 PDF 기능을 사용해 **bid.extract 자체에 직접 전달**한다. 프롬프트의 해당 파일명과 PDF 제목을 연결하고 전사문이 없음을 표시한다. 분류/메타데이터에 PDF가 전달된 것만으로 통합 추출 입력에 포함됐다고 보지 않는다. 문서별 OCR/전사와 원본 PDF 입력을 혼동하지 않는다.

추출 전용 경로에서는 읽지 못한 비PDF·누락된 원본 PDF·PDF 미지원 모델·전체 입력 한도 초과를 유료 호출 전에 오류로 드러낸다. 일부 첨부를 조용히 빼지 않는다. 문서 자체는 로컬 파싱 상태를 유지할 수 있으며, 통합 추출 완료를 문서별 메타데이터/전사 완료로 표현하지 않는다.

HWP PAGE 표기나 파서 pages 원소, 시트 순번을 물리 페이지로 저장하지 않는다. 현재 실제 페이지 대응을 확인할 수 있는 PDF의 범위 내 페이지 번호만 저장한다. `source_attachment`는 정확한 첨부 파일명으로 연결한다. 대응하지 않는 파일명/인용은 원문 검토 대상으로 남긴다.

`extra.extraction_source_review`는 문자 그대로 일치, 공백 차이, 인용 부호 차이, 원본 PDF 직접 판독 필요, 없는 인용/첨부, placeholder를 구분한다. 인용을 자동으로 고쳐 만들지 않으며 **이 검사는 기술 의미·조건·완전성 검증이 아니다**. 누락 카테고리 placeholder는 ‘추출에서 확인 못함·원문 확인 필요’이며 공고에 해당 요건이 없다는 확정 사실이 아니다.

`extra.extraction_run`에는 입력 첨부 ID/해시·PDF/텍스트 모드·프롬프트 버전/요청 해시·모델·관련 파라미터와 실제 LLM 로그 ID를 기록한다. 완전한 개정/재분석 추적 기능은 아니다. API 키·제공자 비밀 설정은 넣지 않는다. SDK 물리 요청/JSON 복구/토큰 관측과 원문 대조의 실제 결과는 B5B 로컬 증거 및 `BACKEND_PROGRESS.md`에 남긴다.

## 다음 회사자료 비교의 근거 범위

현재 자료로 비교를 시작할 수 있다. 원본 시험성적서나 모든 제품 도면이 전체 비교의 필수 선행조건은 아니다.

| 자료 | 지금 활용 가능한 범위 | 확대해서 주장하지 않는 범위 |
|---|---|---|
| 제품 카탈로그 p3 왼쪽·소개서 p9, 실제 데이터시트가 추가 제공되면 해당 본문 | 명시된 모델·형식·치수·재질·기재 사양을 해당 항목의 제조사 자료 근거로 비교. 기재 성능도 명시 조건과 주장 수준을 함께 표시 | 검증된 시험 측정값·다른 시험조건의 성능·완제품/시료 대응·원본 성적서 제출 완료 |
| 현재 직접생산·중소기업 원본 | 해당 증명서가 직접 보이는 범위/기간/품목 | 과거 시점 정보망 상태나 다른 자격까지 보유한다고 확정 |
| 관리대장 성능10·55행 | 관련 원본/소유·시험대상·조건을 찾을 위치 후보 | 정식 성적서·확정 제품 연결·공인 시험으로 자동 전환 |
| 소개서 p23 실적 | 소개서에 기재된 실적 주장과 관련 증빙 확인 지점 | 공고 기간·단일 계약·금액·제조규격을 갖춘 실적증명 원본 |

필텍 질문은 카탈로그의 제안 모델/옵션, 관리대장 두 후보의 원본과 시험대상, 순유효면적·고습 시험 조건, 관련 단일 계약 증빙에 한정해 로컬에 준비한다. 원본은 다음 실무자 미팅에서 요청할 자료이며 질문을 발송하지 않았다. 도면은 이 공고의 제출/제작 승인 요건 또는 현 자료로 설치 치수 등을 확인할 수 없는 항목에만 필요성을 설명한다. 비교 결과는 직원의 판단을 지원하며 최종 입찰 결정을 자동 확정하지 않는다.
