# B6E — 현재 자료 비교의 재검증과 업무 분리

기준 `388f55d`, 2026-10-26 서울. 과거 공고2에 현재 정식 자료를 적용한 시뮬레이션이며 기존 요구37개를 수정/삭제/재추출하지 않았다. 초안 생성·제품 자동 선택·워커·LLM 호출은 없다.

## 결과를 읽는 기준

**회사 현재 비교의 실질 변경은 3개**다. req5는 보유 SME 증서의 명의·기업 구분·시작/종료일을 일반 참가 경로에서 대조해 충족, req25는 선택 제품과 미선택 품목의 모든 등록 후보가 요구 MERV 속성을 만족해 충족, req22는 선택 제품의 등록 가스켓과 명시 요구 재질이 달라 보완 필요다. 가스켓 비고/승인 대안까지 부적합으로 확정한 것은 아니다.

회사 비교27개는 **충족4 / 보완1 / 확인 필요22**다. 기존 동일27개는 충족2/확인 필요25였다. 이 3개의 변경을 실제 회사 비교 해소로 센다. 나머지 공고 사실2개·후속 업무8개는 **원문 조건 확인10개**이고 회사 적합성 판정 대상이 아니다. 기존 37개 전체의 호환 `verdict_counts`는 **14/1/22**, HIGH5이지만 **충족14를 회사 충족14로 보고하면 안 된다**. 원문/업무10개 분류 변경은 회사자료로 10개 자격/성능을 추가 입증했다는 실적으로 세지 않는다.

모든 행에 제출 준비 완료/최종 응찰 자격 확인은 false다. 이는 회사 비교 자체를 막는 조건이 아니라 별도 검토 경계다. 예컨대 일반 SME 증서 비교는 완료됐지만 제출 전 공공구매망·새 공고 마감일 효력 확인 업무는 OPEN으로 남는다.

## 규칙 수정

- `rules.evaluate`는 검토 표시에 도달하기 전에 지원되는 해석을 현재 입력으로 재검증한다. 과거 `interpretation_review`는 요구조건에 그대로 보존하고 새 `rule_trace.assessment.interpretation_revalidation`에 원 표시, 실제 비교된 부분, 남은 부분, RESOLVED/PARTIAL/UNRESOLVED를 저장한다. 미지원/미확인 해석은 기존 보류 경로를 유지한다.
- SME의 일반 경로와 조합/특별법인/신청 중 예외를 분리했다. 일반 경로를 증서로 입증하면 해당 예외는 NOT_NEEDED_FOR_GENERAL_ROUTE이며 예외 서류를 다시 요청하지 않는다. 명의 다름/기간 미상은 확인 필요, 만료는 보완 필요다. 실제 회사에는 일반 경로의 현재 증서 비교만 적용했으며 외부 자격 승인을 소급하지 않았다.
- 품목별 선택 제품·각 후보를 실제 비교한다. 미선택 항목의 형식·치수는 직원 선택을 기다린다. 이미 선택한 제품의 확인된 차이는 다른 품목 미선택에 가려지지 않는다. **모든 등록 후보가 해당 속성을 입증하는 경우** 그 속성만 선택과 독립적으로 비교할 수 있다. 후보 중 하나라도 다른 값/자료 부족이면 확인 필요로 남는다. 후보 1순위를 자동 확정하거나 부적합 후보를 임의로 제외하지 않는다.
- 재질 계열 일치를 순도/처리 상태 일치로 확대하지 않는다. 기본 재질을 마감/코팅으로, 카탈로그 등급을 판본/공인 시험으로, 사용 습도를 고습 차압변동 측정으로, 페어 풍량/면적을 시스템/순유효면적으로 대체하지 않는다. 원본 SHA가 다르면 비교 완료를 인정하지 않는다.
- 공고 사실, 회사 현재 비교, 후속 제출/검사 업무를 분리했다. 공고 조건은 실제 인용 위치와 숫자 의미까지 대조한다(예: 연→개월, 제출 일수/부수, 심사 통과점수/하한율, 시험 종료조건). 회사 업무가 아직 실행되지 않았다는 이유로 현재 속성 비교를 일괄 중단하지 않는다. 업무는 OPEN/CONDITIONAL이며 완료로 저장하지 않는다. 문서 종류·시점·부수·조건·원 요구 전문을 업무 parameters에 보존했다.
- 규칙으로 결정된 assessment를 LLM이 덮어쓰지 않는다. 이번37개는 모두 규칙 결과이며 LLM0이다. 수동 판정은 keep_modified로 보존하고 수동 행의 자동 assessment를 현재 판단처럼 제공하지 않는다. 새 이력에는 `rule_trace`도 저장한다. 옛 이력 복원 시 원 AnalysisRun 출력의 trace를 복원하거나 미상으로 두며 새 trace를 옛 결과에 붙이지 않는다.

## 이미 제공된 원본에서 추가로 확인한 정보

카탈로그 문서10 물리3쪽을 직접 시각 확인해 두 제품의 Liner/End cap 기본 재질 근거를 `manual_product_components.{product_id}` **2행**에 추가했다. 물리쪽·SHA·사람 전사 원문·미확인 마감을 명시했다. 기존 프레임 요약을 부품값으로 추정하지 않았고 기존 Product 행을 변경하지 않았다. 기본 재질은 재요청하지 않으며 **분체도장 여부/변경 옵션만** 남겼다. 메타데이터의 원본/쪽/제품/인용 필드 불일치는 사용하지 않는다.

req14는 제공된 문서6의 실제 확약서 문단을 직접 재대조했다. 저장 인용의 따옴표 누락으로 발생한 QUOTE_NOT_FOUND는 원 요구/API에 그대로 두고, `manual_requirement_revalidation.14` **1행**에 명시적 추가 인용을 남겼다. 원문/추출 텍스트 SHA·원 인용·새 인용을 연결하며 자동 문장 교정/인용 추정은 없다. 새 assessment 근거는 EXACT_MATCH/추출 텍스트 위치이고 원 인용 불일치도 함께 반환한다. HWP 물리 페이지를 만들지 않았다. 이미 존재하는 원본을 다시 제출하라는 요청을 없앴다.

회사/인증/제품 행·기존52 메타데이터·원본을 변경하지 않고 이 **메타데이터3행만 추가**했다. 실제 값·원문/상세 대조표·백업은 Git 제외 `.venv/b6e/`에 있다.

## 읽기 API 계약

- 판정/요구조건 include=evaluation에 **`assessment`** 추가(저장된 `rule_trace.assessment`의 읽기 전용 투영). `scope`는 CURRENT_COMPANY / CURRENT_DOCUMENTED_QUALIFICATION / NOTICE_FACT / FUTURE_OBLIGATION이다. 기존 필드/권한/수동 기능을 유지한다.
- `current_company_verdict`, `checks[]`(요구/현재 값/대조 상태/근거), `item_comparisons[]`(선택과 모든 후보 비교), `interpretation_revalidation`, `missing_inputs[]`, `follow_up_tasks[]`를 제공한다. 수동 수정본은 MANUAL_REVIEW_REQUIRED이며 옛 자동 상세를 새 수동 판단처럼 보여주지 않는다. 옛 비구조화 결과도 GET에서 재판정하지 않는다.
- 비교표 **`stored_result.assessment`**, **`assessment_summary`**, **`input_requests`** 추가. 전체37개 보존, 회사 비교27/공고·업무10을 명시한다. `notice_or_workflow_MET_is_company_compliance=false`. 프런트는 scope와 함께 판정을 표시하고 공고/업무의 MET를 회사 충족 배지/참가 가능 점수로 합산하지 않아야 한다. 기존 평면 집계는 호환용이며 위14/1/22를 사업 적합성 수치로 사용하지 않는다.
- 입력 요청은 **23개 고유 키**로 합쳤다. 품목2 선택은 여러 행에 걸쳐도 `items.2.matched_product_id` 한 요청이다. `requirement_ids`·`conditions_by_requirement`를 사용해 관련 행을 함께 표시한다. 23개가 별도 원본23개를 뜻하지 않는다. 하나의 성적서/사양 원본이 여러 측정·판본 필드를 입증하면 한 번 제공한 원본으로 연결하고 같은 파일을 반복 요청하지 않는다. 확인된 SME 증서/부품 기본 재질은 재요청하지 않는다.
- 새 추가 인용에는 `quote_origin=EXPLICIT_MANUAL_ADDITIONAL_QUOTE`, `original_location`, `stored_requirement_quote_modified=false`, 원문 SHA/텍스트 오프셋을 준다. 옛 source_location을 조용히 수정하지 않는다. HWP 오프셋은 기존 B6B 계약대로 텍스트 SHA와 함께 사용하며 실제 HWP 쪽이 아니다.
