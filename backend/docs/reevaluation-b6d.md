## 입력과 출처 검증

`formal_sources`는 추가된 내부 서비스 옵션이며 기존 호출의 기본값은 유지한다. 회사 필드 전체와 인증의 명의·종류·번호·범위·발급처·발급/시작/종료일·제한 notes·문서 ID/SHA·수동 근거를 보존한다. 미상 값은 null/빈 값 그대로다. LLM 요청은 회사 자료를 `bid_context.CURRENT_FORMAL_COMPANY_DATA`에 한 번 싣고 각 요구가 이를 참조한다. 실제 입력77,945자/한도150,000자로 잘림이 없었다. 한도 초과는 잘라서 진행하지 않고 중단한다.

B6B SourceLocator가 실제 업로드 SHA와 물리쪽을 대조한다. 검토 메타데이터와 현재 값/파일이 다르면 실행을 거부한다. 사람 전사 인용은 `HUMAN_TRANSCRIBED_NOT_MACHINE_CHECKED`로 유지하며 OCR 일치나 진위 확인이라고 표시하지 않는다. 인증 근거는 정확한 `(certificate ID, page, quote)` 허용 목록만 통과한다. 문서 ID를 인증 ID로 오인하거나 원 인용과 다른 인용은 보정/추정 없이 제외한다. 실제 LLM 인용10개가 제외됐다. 기존 요구의 저장 공고 인용은 별도로 유지했고 req14 인용 불일치·req6 스캔 쪽만 확인·HWP 물리쪽 미상도 그대로다.

이번 미처리5개는 보증·검사·심사·복합 자격 등 직접 이행/적용 검증기가 없는 범위다. 실제 인증 인용도 그 절차 완료를 증명하지 않으므로 LLM의 미검증 서술·답변을 게시하지 않고 확인 필요와 내부 확인 행동을 기록한다. 원 응답은 비공개 호출 로그/영수증에 남는다. 인증이 없다는 생성 문장을 결과로 쓰지 않는다. 결과 개수에 맞춘 조정은 하지 않았다.

첫 실행은 날짜 객체를 JSON 추적에 저장하다 실패했다. 완료 저장이 원자적으로 롤백됐고 실제 기존 판정37/이력45/초안4 원행 동일을 확인했다. 날짜를 ISO 문자열로 직렬화하도록 수정하고 **실제 LLM 프롬프트 변수 완전 동일·회사 입력 동일(수정 코드 제외)**을 확인해 수신 완료 응답/로그3을 재사용했다. 추가 유료 요청0. 실패 실행1은 FAILED/outputs={}, 재완료 실행2는 COMPLETED, 초안 실행3–6도 COMPLETED로 보존했다. B6C의 입력/수동 결과 변경 검사와 keep_modified 정책을 사용했다. 실제 수동 판정은0개였으며 수동 보존/입력 변경 중 중단은 격리 테스트로 확인했다.
